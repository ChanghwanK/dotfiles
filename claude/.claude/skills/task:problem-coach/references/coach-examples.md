# 코치 판정 예시 (코치 전용)

코치가 판정 수준을 맞추기 위한 기준이다. 사용자에게 보여 주지 않고, 판정 이유(reason)에 이 문서의 문장을 인용하지 않는다.
사례는 가상이다. 사용자의 실제 사례와 섞지 않는다.

---

## A. 문제 정의 판정 예시

가상 사례: 사내 패키지 미러(프록시 저장소) 디스크가 가득 차서 빌드가 실패한다.

### A1. Bad: 상태 서술

> 패키지 미러 디스크가 자주 가득 차서 빌드가 실패한다. 디스크를 늘리거나 정리해야 한다.

| 항목 | 판정 | 이유 |
|------|------|------|
| 관측 | 부분 | "자주"만 있고 횟수, 기간, 출처가 없다 |
| 연결 | 미충족 | 결론 자리에 해결책(증설, 정리)이 있고, 상태가 왜 생기는지에 대한 설명이 없다 |
| 범위 | 미충족 | 결론이 설정값 조정(증설)뿐이고, 그 상태를 만드는 경로가 지목되지 않았다 |
| 영향 | 부분 | 빌드 실패는 있으나 누구에게 얼마나인지 없다 |

`conclusion_type`: 상태

### A2. Bad: 사람 탓으로 끝남

> 지난 90일 동안 디스크 100% 도달 4회(모니터링 기록), 매번 빌드가 2~3시간 멈췄다. 담당자가 정리 작업을 깜빡해서 생긴다.

| 항목 | 판정 | 이유 |
|------|------|------|
| 관측 | 충족 | 횟수, 기간, 출처, 중단 시간이 있다 |
| 연결 | 미충족 | "깜빡해서"를 받치는 관측이 없고 추정만 있다. 대안 설명과 둘을 가르는 관측도 없다 |
| 범위 | 미충족 | 결론이 사람의 행동(깜빡함)에서 끝난다 |
| 영향 | 부분 | 중단 시간은 있으나 영향받는 대상이 없다 |

`conclusion_type`: 상태 (사람 탓은 구조 결론이 아니다)

### A3. Good: 구조에 닿음

> 관측: 90일간 100% 도달 4회(모니터링 기록). 정리 후 평균 21일 만에 다시 도달했다. 저장소 설정의 보존 기한 항목은 비어 있다(저장소 설정 화면).
> 결론(구조, 가설): 캐시 아티팩트에 보존 기한이 없고 삭제가 수동 정리에만 기대서 사용량이 계속 늘어난다.
> 대안: 최근 올라온 소수의 대형 패키지가 용량을 채웠을 가능성.
> 가르는 관측: 도달 직전 저장소 사용량 리포트에서, 마지막 접근이 90일을 넘은 아티팩트가 용량 대부분을 차지하면 결론, 최근 30일 안에 올라온 소수 패키지가 대부분이면 대안.
> 영향: 도달할 때마다 전사 빌드가 2~3시간 멈춘다. 영향 인원은 회당 약 40명이다(빌드 대기 로그).

| 항목 | 판정 | 이유 |
|------|------|------|
| 관측 | 충족 | 횟수, 재도달 주기, 설정 상태와 각각의 출처가 있다 |
| 연결 | 충족 | 재도달 주기와 비어 있는 보존 설정이 설명을 받치고, 두 설명이 서로 다른 결과를 예측하는 관측이 있다 |
| 범위 | 충족 | 바꿀 수 있는 고리(보존 기준, 삭제 경로)를 지목했다 |
| 영향 | 충족 | 대상, 시간, 규모가 있다 |

`conclusion_type`: 구조

### A4. Good: 근거 있는 "구조 확대 불필요"

> 관측: 90일간 1회 도달. 해당 일자에 대용량 이미지 1건 업로드(업로드 로그), 그 외 기간 사용률은 40~50%로 평탄하다.
> 결론(구조 확대 불필요): 재발 경로가 보이지 않고 사용량이 평탄하다. 영향은 1회 1시간이고, 업로드 크기 제한을 두려면 업로드 정책 변경이 필요해 비용이 크다. 지금은 구조를 바꾸지 않는다.
> 대안: 업로드 크기 제한이 없는 것이 구조 원인일 가능성. 같은 크기의 업로드가 아직 다시 없어 검증되지 않았다(미검증). 가르는 관측: 같은 크기의 업로드가 다시 들어왔을 때 디스크가 다시 차는가. 그때 다시 정의한다.
> 영향: 빌드 1시간 중단 1회.

| 항목 | 판정 | 이유 |
|------|------|------|
| 관측 | 충족 | 횟수, 원인 이벤트, 평탄한 사용률과 출처가 있다 |
| 연결 | 충족 | 결론이 관측과 이어지고, 대안을 기각하지 않고 미검증으로 밝히며 가를 관측을 정해 두었다 |
| 범위 | 충족 | 구조를 넓히지 않는 근거(일회성, 작은 영향, 큰 변경 비용)가 있다 |
| 영향 | 부분 | 시간은 있으나 영향받는 대상이 없다 |

`conclusion_type`: 구조 확대 불필요. 구조 결론이 아니라는 이유로 낮게 판정하지 않는다. "같은 일이 다시 없었다"는 대안을 기각하는 근거가 아니다(다시 노출될 기회가 없었을 뿐이다).

### A5. Good: 근거 있는 "원인 미확인"

> 관측: 90일간 100% 도달 2회(모니터링 기록). 두 번 모두 새벽 3~4시이고, 사용량 그래프에서 1시간 안에 30%p가 늘었다.
> 결론(원인 미확인): 급증의 원인을 아직 모른다.
> 후보: (1) 업스트림 동기화 작업이 한 번에 대량으로 받아 옴 (2) 외부 CI가 새벽에 대량 다운로드를 일으킴.
> 가르는 관측: 급증 시각의 동기화 작업 로그와 접근 로그의 요청 주체. 동기화 로그에 대량 수신이 있으면 (1), 접근 로그에 특정 외부 주체의 요청이 몰려 있으면 (2).
> 영향: 회당 빌드 2시간 중단, 약 40명(빌드 대기 로그).

| 항목 | 판정 | 이유 |
|------|------|------|
| 관측 | 충족 | 횟수, 시각, 증가 폭과 출처가 있다 |
| 연결 | 충족 | 원인을 단정하지 않고 후보 둘과 그 둘을 가르는 관측을 정했다 |
| 범위 | 충족 | 후보마다 바꿀 수 있는 고리를 가리키고, 다음에 잴 관측이 정해져 있다 |
| 영향 | 충족 | 대상, 시간, 규모와 출처가 있다 |

`conclusion_type`: 원인 미확인. 원인을 단정하지 않았다는 이유로 낮게 판정하지 않는다.

## B. 코치 출력 예시

### Good: A2 초안에 대한 판정 (train, draft)

```json
{
  "question_id": "Q5",
  "conclusion_type": "상태",
  "rubric": {
    "observation": {"level": "충족", "reason": "횟수, 기간, 출처, 중단 시간이 있습니다"},
    "connection": {"level": "미충족", "reason": "설명을 받치는 관측이 없고 추정만 있습니다. 대안 설명과 둘을 가르는 관측도 없습니다"},
    "scope": {"level": "미충족", "reason": "결론이 사람의 행동에서 끝납니다"},
    "impact": {"level": "부분", "reason": "중단 시간은 있으나 영향받는 대상이 없습니다"}
  }
}
```

- 이유는 사용자 문장에 있는 것과 없는 것만 말한다
- 연결과 범위가 함께 미충족이다. 결론이 사람에서 끝나는 것이 더 근본적인 빈칸이라 범위의 빈칸을 채우게 하는 질문을 목록에서 골랐다

### Bad 1: 이유에 구조 후보를 흘림

```json
"scope": {"level": "미충족", "reason": "보존 기한 정책이 없는 것이 진짜 원인일 수 있습니다"}
```

사용자가 찾아야 할 구조를 코치가 말했다. 사용자는 받아 적기만 하고, 그 사례는 연습이 되지 않는다.

### Bad 2: 목록에 없는 유도형 질문

```
질문: 캐시 아티팩트에 보존 기한이 설정되어 있습니까?
```

질문 안에 답(보존 기한)이 들어 있다. 질문은 `question_id`로만 고르고 문구를 만들지 않는다.

### Bad 3: 고쳐 쓴 문장이나 모범 문장 제시

```
"connection": {"level": "부분", "reason": "다음처럼 쓰면 됩니다: 사용량이 단조 증가하는 구조이므로..."}
```

문제를 대신 정의했다. 이 스킬의 목표와 정면으로 어긋난다.

### Bad 4: 구조 결론 편애

A4에 `"scope": {"level": "미충족", "reason": "구조적 원인을 찾지 않았습니다"}`

근거 있는 "구조 확대 불필요"는 정당한 결론이다. 구조 결론을 강요하면 구조처럼 들리는 문장을 만드는 훈련이 된다.

### Bad 5: 가설을 확정 사실로 평가

A3에 `"connection": {"level": "충족", "reason": "원인을 정확히 짚었습니다"}`

코치는 원인이 맞는지 모른다. 판정 대상은 서술 품질이다. "설명이 관측과 이어지고 대안을 가르는 관측이 있다"처럼 쓴다.

### Bad 6: 칭찬, 격려, 추가 조언

```
"impact": {"level": "충족", "reason": "아주 잘 쓰셨습니다! 다음에는 비용 영향도 함께 보시면 좋겠습니다"}
```

판정과 무관한 말이고, 다음에 무엇을 볼지까지 알려 줬다. 이유는 있는 것과 없는 것만 쓴다.

### Bad 7: "판정 불가" 남용

A1에 `"impact": {"level": "판정 불가", "reason": "영향 정보가 부족합니다"}`

문장에 정보가 없으면 미충족이다. 판정 불가는 사례 특성상 판단 자체가 불가능할 때만 쓴다.

### Bad 8: 약한 항목과 무관한 질문 선택

A2에 `"question_id": "Q8"` (영향 질문)

가장 약한 항목은 연결과 범위(사람 탓)다. 영향 질문은 이 초안의 핵심 빈칸을 채우게 하지 못한다.
