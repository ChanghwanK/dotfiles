# 설계 근거: 첫 실행 세션 회고 (2026-09-09, EBS throughput 작업)

이 스킬은 "EBS root 볼륨 throughput 125 → 250 MiB/s" 작업을 면접 형식으로 회고한 세션에서 나왔다.
그 세션에서 잘 된 것·투머치였던 것·빠진 것을 설계 결정에 매핑한 기록이다.

| 팩트 시트를 답변보다 먼저 고정 | 숫자 하나가 틀리면 전체가 흔들림 | Step 2 + 사용자 확인 |

| 세션에서 한 일 | 문제 | 결정 |

## 첫 실행 케이스 요약 (재현 참고용)

- 대상: riiid/kubernetes #8843 (prod default-v5 gp3 throughput 125 → 250)
- 체인: #8774 (계측 준비, 발단 기록) → #8843 (변경) → #8845 (A/B 실험 자산) → #8855 (정리) → #8857 (wiki 반영)
- 발단은 #8774에만 있었다: Karpenter consolidation 직후 파드 28개가 캐시 없는 신규 노드로 몰려 23GB 이미지 동시 pull, root 볼륨 6분 포화
- 채택 근거(실험 결과 표)는 #8843 코멘트에만 있었다
- 취약점 3종이 모두 나왔다: prod before/after 미측정(미완료), 250은 fitted value(설계 한계), %util·1-idle 오독(틀렸던 것)
- 이 케이스를 다시 실행하면 이 스킬의 회귀 테스트가 된다

## 첫 실행에서 발견한 결함과 수정 (2026-09-09)

| 결함 | 증상 | 수정 |

면접관이 실제로 하는 건 후자다. 그리고 why 체인의 재료(중간 판단)는 PR이 아니라 세션에만 있다.
