# Recommend 모드: 다음 학습 주제 추천

`/learn` 세션 중 다음 주제를 고를 때 쓴다. 시니어/스태프 성장 관점에서 사용법보다 설계 철학·내부 동작·트레이드오프 주제를 고르고, 주제마다 왜 중요한지 근거를 단다.

## 절차

1. 사용자 메시지에서 도메인을 뽑는다 (예: "AWS network", "Kubernetes", "Observability")
2. 수준(easy / medium / hard)을 확인한다. 대화에서 이미 명확하면 생략
3. 아래 형식으로 추천한다
4. 사용자가 번호를 고르면 그 주제로 Phase 0(Deep-dive)부터 시작한다

## 분류와 개수

| 레이어 | 기대 수준 | easy | medium | hard |
|--------|-----------|------|--------|------|
| **Foundation** (선수 지식·기초 원리) | "왜 이렇게 동작하는지" 설명 | 3~4개, 상세 | 2개, 빠르게 | 1개, 복습용 |
| **Core** (도메인 핵심 기술) | 설계 의사결정 가능 | 2~3개, 개요 | 3~4개, 상세 | 2~3개 |
| **Advanced** (심화·최적화·엣지 케이스) | 팀의 기술 방향 리드 | 1개, 언급만 | 2~3개, 개요 | 3~4개, 상세 |

## 출력 형식

```
## {domain} 학습 추천 (시니어/스태프 관점)
- Level: {level} / 도메인: {domain}

### Foundation: 기초 원리   (Core: 핵심 기술, Advanced: 심화/리더십도 같은 표)
| # | 주제 | 난이도 | 시니어/스태프에게 중요한 이유 |

### 학습 순서 가이드
[Foundation A] → [Core B] → [Advanced C]
       ↘ [Core D] → [Advanced E]

> 번호를 선택하면 해당 주제로 Deep-dive 학습 세션을 시작합니다.
> "전체 커리어 관점에서 뭘 공부해야 할지"는 `/learn:growth-maker`를 사용하세요.
```
