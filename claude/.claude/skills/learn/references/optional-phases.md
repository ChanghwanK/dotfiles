# 선택 단계: Phase 2 How · Phase 3 What-if · Phase 4 Apply

전환 질문의 형식은 SKILL.md "Phase 전환 질문 (공통 형식)"을 따르고, 여기서는 Phase별 초점만 정한다.

## Phase 2: How

Phase 1의 동작 원리 다이어그램과 특징 목록을 지도로 삼아 컴포넌트와 특징을 하나씩 깊게 판다. Overview를 다시 그리지 않는다. 다룰 것: 컴포넌트 내부, 핵심 코드 경로(critical path), 데이터 흐름(입력 → 변환 → 출력), 성능·동작을 결정하는 자료구조/알고리즘.

**Feature Explanation Pattern**: Phase 1에서 고른 특징마다 아래 네 줄로 설명한다.

```
**Consolidation (빈 패킹 최적화)**
- 해결하는 문제: 노드가 underutilized 상태로 방치되면 비용 낭비
- 동작 방식: 주기적으로 utilization 평가 → 워크로드 이동 → 빈 노드 제거
- 트레이드오프: 비용 절감 vs Pod 재배치로 인한 일시적 중단
- 대안: Cluster Autoscaler의 scale-down (노드 단위 판단, 빈 패킹 없음)
```

| Level | 깊이 | 패턴 적용 범위 |
|-------|------|----------------|
| easy | 다이어그램의 컴포넌트 1~2개 동작 순서 | 핵심 특징 1~2개, 간략히 |
| medium | 주요 인터페이스, 설정 옵션, 동작 모드 | 주요 특징 전부, 대안은 이름 + 한 줄 |
| hard | KEP·RFC·설계 문서 수준 인터페이스와 내부 동작 | 모든 특징, 대안의 구현 차이까지 |

**전환 질문 초점 (Phase 2 → 3)**: 초급은 주요 컴포넌트 역할과 데이터 흐름의 시작·끝, 중급은 핵심 동작 원리 재현과 특정 입력이 들어올 때의 내부 과정 추적, 고급은 이 내부 구조가 운영에서 드러나는 상황과 깨지거나 병목이 되는 조건·증상. Socratic 제목은 "How를 고민할 주제", 다음 Phase 질문은 "왜 다른 접근이 아닌 현재 방식인가"(What-if로 연결).

## Phase 3: What-if

실제로 고려됐거나 다른 프로젝트가 고른 대안 설계 1~2개를 비교하고, 현재 설계가 채택된 결정적 요인을 쓴다.

```
| 기준 | 현재 설계 | 대안 A | 대안 B |
| 복잡도 / 성능 / 운영 부담 / 확장성 | ... | ... | ... |
```

**전환 질문 초점 (Phase 3 → 4)**: 초급은 현재 설계와 대안의 핵심 차이와 비교 기준별 위치, 중급은 특정 상황에서 어느 쪽이 맞는지와 유불리의 구조적 원인, 고급은 트레이드오프가 실제 문제가 되는 상황과 조건(트래픽 규모, 팀 구조 등)이 바뀌면 선택이 뒤집히는 임계점. Socratic 제목은 "What-if를 고민할 주제", 다음 Phase 질문은 실제 적용 시 고려할 점.

## Phase 4: Apply

학습 내용을 SOCRA AI 인프라에 연결한다: 현재 사용 현황, 새로 도입하거나 개선할 영역, 우리 환경 특성상 고려할 점(EKS prod/global/stg/dev/idc, Istio, ArgoCD, Karpenter, IDC GPU 클러스터는 Proxmox + Cluster API).
