# tasks:capture: 추출 규칙 참조

제목 합성 + Description 추출의 예시 및 엣지 케이스 참조 문서.
실행 시 매번 로드하지 않음. 판단이 애매한 경우에만 참조한다.

---

## 예시 테이블

| 입력 | 제목 (합성) | Description |
|------|------------|-------------|
| `CI 파이프라인 캐시 최적화` | CI 파이프라인 캐시 최적화 | 없음 (추가 정보 없음) |
| `P1 긴급 프로덕션 OOM 이슈 분석` | 프로덕션 OOM 이슈 분석 | 없음 (추가 정보 없음) |
| `내일까지 독서 50페이지 개인` | 독서 50페이지 | 없음 |
| `나중에 Karpenter 튜닝 실험` | Karpenter 튜닝 실험 | 없음 |
| `[알람 생성] Pod cpu 및 memory 리소스가 request 대비 사용량이 낮은 경우 (window는 7일) 알람` | [알람 생성] Pod 리소스 Request 대비 사용량 알람 | Pod cpu/memory request 대비 사용량 낮을 때 알람. window 7일 기준. 리소스 낭비 감지용. |
| `P2 코드 리뷰` | 코드 리뷰 | 없음 |
| `slack app 통합, devops/ArgoCD 등 다양하게 사용 중인 app을 통일하는 것이 목표 why? 접근 권한이 없음 유지보수 안됨` | Slack App 통합 및 중앙화 | devops, ArgoCD 등 app을 통일하는 것이 목표. 접근 권한 없음, 유지보수 안됨. |
| `MY 주간 독서 목표 설정` | 주간 독서 목표 설정 | 없음 |

## 엣지 케이스 Q&A

### Q: 30~50자 중간 길이, 추가 정보가 애매한 경우는?

예: `"Karpenter 노드 라벨 설정 테스트"` (20자) → 단순 액션, 추가 정보 없음 → description 없음.
예: `"CI 파이프라인 캐시 최적화 (빌드 시간 단축 목표)"` → 괄호 안이 추가 정보(이유) → description 자동 생성.

길이는 보조 신호. **"괄호 안 설명", "왜냐하면", "이유:", 쉼표 이후 설명**이 있으면 추가 정보로 판단.

### Q: [카테고리 태그]가 있는데 제목이 짧아도 되나?

`[알람 생성] Pod CPU 알람` → 짧고 명확하면 OK. 30자 이하라도 추가 정보가 없으면 description 불필요.

### Q: Category "MY" 감지 실패 우려가 있는 경우

"개인", "MY", "personal", "사적" 외에도 맥락상 개인 용무(독서, 운동, 취미)임이 명확하면 MY로 설정 가능.
단, 업무 여부가 불명확하면 WORK 기본값을 적용하고 사용자에게 Category 선택 옵션을 추가해도 무방.
