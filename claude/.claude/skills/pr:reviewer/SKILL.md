# pr:reviewer Skill

PR을 등급 판정한 뒤, 이해가 필요한 등급이면 리뷰어의 질문과 모범답안을 함께 제시하고(기본), 요청 시에만 closed-book 채점으로 판정하며, 아니면 내용만 정리한다.

---

## 핵심 원칙

- **기본은 답변 공개, 채점은 요청 시에만.** A 등급의 기본 출력은 "리뷰어가 물을 질문 + 그 모범답안"이다. 소유자가 읽고 스스로 빈틈을 확인하는 용도이며 판정을 내리지 않는다. 채점 모드는 "채점해"·"질문해"로 명시할 때만 연다.
- **채점 모드에서는 답하지 못하면 내 작업이 아니다.** 판정 대상은 코드의 옳음이 아니라 소유자의 방어 가능성이다. 코드가 옳아도 소유자가 설명하지 못하면 `보류`다. 채점 모드 중에 모범답안을 공개하는 것은 이해가 아니므로 공개해도 판정은 바뀌지 않는다.
- **등급은 스크립트가 정하고 예외는 사유와 함께 남긴다.** 스크립트 등급을 올리는 것은 자유이고, 내리는 것은 출력에 사유를 적어야만 한다. 스크립트가 보지 못하는 것(문서 변경이지만 운영 절차를 바꿈, 테스트가 변경 경로를 덮지 않음, `diff_truncated`)은 Claude가 올린다.
- **질문은 퀴즈가 아니라 리뷰어의 질문이다.** 실제 리뷰어가 승인 전에 묻는 것만 묻는다. 모든 모범답안은 diff·PR 본문·파일 경로·값에 근거해야 하며, 근거가 없으면 `GAP`으로 보고하고 지어내지 않는다.
- **closed-book (채점 모드).** 소유자는 diff를 다시 열지 않고 답한다. "동작한다", "테스트 통과했다", "에이전트가 확인했다"는 답이 아니다.
- **채점은 실질로 한다 (채점 모드).** 표현이 모범답안과 달라도 메커니즘과 근거가 맞으면 통과다. 반대로 매끄러운 문장이라도 근거(파일·값·쿼리)가 없으면 부분이다.
- 스크립트만 호출한다. `gh`·`git` 직접 호출 금지.

## 워크플로우

### Step 1: 대상과 지시 해석

| 신호 | 해석 |
|------|------|
| PR 번호, `#N`, PR URL | 그 PR |
| 아무것도 없음 | 현재 브랜치(PR 미생성이면 로컬 커밋 기준, 범위 줄에 명시) |
| "A로", "리뷰어 모드로" | 등급과 무관하게 리뷰어 답변 모드(질문 + 모범답안) 강제 |
| "채점해", "질문해", "퀴즈로", "답 숨기고" | 등급과 무관하게 채점 모드 강제 (질문만 내고 멈춘 뒤 답을 받아 판정) |
| "요약만", "정리만" | 등급과 무관하게 요약 모드 강제. 단, 스크립트 등급이 A였으면 출력 첫 줄에 그 사실을 남긴다 |

### Step 2: 등급 판정 (스크립트)

```bash
python3 /Users/changhwan/.claude/skills/pr:reviewer/scripts/triage_pr.py triage
python3 /Users/changhwan/.claude/skills/pr:reviewer/scripts/triage_pr.py triage --ref 8870
```

읽어야 할 필드:

| 필드 | 의미 |
|------|------|
| `grade` / `mode` | `A`→`reviewer`(기본은 답변 모드, 지시가 있을 때만 채점 모드), `B`·`C`→`summary` |
| `grade_reasons` | 등급을 결정한 규칙의 사유. 출력에 그대로 인용한다 |
| `adjustment` | 스크립트가 스스로 조정한 내역(관례 배포 하향, CI 부재 상향). 있으면 출력에 남긴다 |
| `flags` | `silent_failure` `prod` `one_way_door` `contract` `security` `decision` `runtime` `note` |
| `axes[]` | 리뷰어 모드에서 물을 축과 질문 취지. 최대 5개 |
| `files[]` | 파일별 등급·환경·플래그·매칭 규칙(`rules[].sample`은 diff에서 잡힌 실제 문자열) |
| `verification` | `ci_in_repo`, `tests_in_diff`, `check_commands` |
| `context` | PR 본문·커밋·diff. 질문과 모범답안의 유일한 근거 |

`success: false`면 error를 그대로 보여주고 멈춘다. 리포 밖에서 실행했거나 `gh` 인증이 없는 경우다.

### Step 3: 등급 조정 (Claude)

스크립트 결과를 `context.diff`와 대조해 한 번만 판단한다.

- **올린다** (사유 출력): B 파일인데 diff가 테스트 없는 경로를 바꿈, C 문서인데 runbook·온콜 절차·롤백 절차를 바꿈, `diff_truncated: true`, `note` 플래그(미완 표식이 diff에 남음).
- **내린다** (사유 출력 필수): A 규칙에 걸렸지만 실제 변경이 주석·설명 문자열뿐일 때처럼, 규칙의 사유가 이 diff에 성립하지 않는 경우만.
- 관례 배포(`adjustment`에 `image-bump`)는 내리지 않는다. 스크립트가 이미 내렸다.

### Step 4a: 요약 모드 (B·C)

```
Read /Users/changhwan/.claude/skills/pr:reviewer/assets/output-template.md
```

"요약 모드" 템플릿으로 렌더한다. 질문은 하지 않는다. 반드시 들어가야 하는 것:
- 등급과 그 사유(`grade_reasons`), 조정 내역
- 변경 내용을 파일 그룹이 아니라 **행동 단위**로 정리(무엇을 왜 바꿨는지, PR 본문에 근거)
- 이 PR을 대신 검증하는 장치(`verification.check_commands`, CI, 파이프라인)와 그 장치가 덮지 않는 것 한 줄
- 리뷰어 모드로 올리고 싶으면 "A로"라고 말하면 된다는 안내 한 줄

### Step 4b: 리뷰어 답변 모드 (A, 기본)

1. `axes[]`의 각 축에 대해 질문 하나를 쓴다. 축의 `prompt`는 취지이지 문장이 아니다. 이 PR의 구체적 파일·값·규칙을 넣어 리뷰어가 실제로 물을 문장으로 만든다.
2. 각 질문 바로 아래에 모범답안을 `context`에서 써서 **함께 공개한다**. 답안은 diff의 파일·키·값·수치를 인용해야 하며, 근거가 없는 축은 질문은 하되 답안 자리에 `GAP`을 적고 "근거를 찾지 못한 항목"에 올린다.
3. 플래그별 필수 요소 (질문과 답안 모두에 반영):
   - `silent_failure`: 실패 양상은 "무엇이 조용히 사라지거나 중복되는가"와 "그것을 어떤 지표·쿼리로 알아차리는가"를 함께 다룬다.
   - `prod` 또는 `one_way_door`: 롤백은 소요 시간과 "되돌려도 남는 것"을 다룬다.
   - `contract`: 배포 순서(백엔드 먼저)를 다룬다.
   - `security`: 넓어진 표면과 그것이 에러 없이 열린다는 점을 다룬다.
4. 템플릿 "리뷰어 답변 라운드"로 렌더하고 종료한다. 판정(`내 작업`/`보류`)을 내리지 않고, 채점 루프로 들어가지 않는다. 마지막에 "채점 모드로 다시 돌리려면 '채점해'"라고 한 줄만 안내한다.

### Step 4c: 채점 모드 (A, "채점해"·"질문해" 지시 시에만)

Step 4b의 1·3과 같이 질문을 만들되, 모범답안은 `context`에서 미리 준비하고 **공개하지 않는다**. 템플릿 "리뷰어 질문 라운드"로 렌더하고 **멈춘다.** 같은 메시지에서 답하지 않는다. 이후는 Step 5로 간다.

### Step 5: 채점과 판정 (루프, 채점 모드 전용)

소유자가 답하면 템플릿 "채점·판정 라운드"로 채점한다.

- 항목별 `통과` / `부분` / `미달`. 교정은 무엇이 빠졌는지를 diff의 구체물(파일·키·값·라인)로 짚는다. 모범답안은 이때 공개한다.
- `부분`은 그 빈틈만 겨누는 후속 질문 1개. `미달`은 **읽을 곳**(파일 경로, 필요하면 라인·키)을 지정하고 같은 축을 다른 문장으로 다시 묻는다. 원문 질문을 그대로 반복하지 않는다.
- 판정:
  - 모든 축 `통과` → **`내 작업`**: 머지 가능. 종료 요약을 낸다.
  - 하나라도 `부분`/`미달` → **`보류`**: 다음 라운드로 간다. 라운드는 최대 3회. 3회 안에 통과하지 못하면 `보류`로 종료하고 남은 축을 무지 항목으로 적는다.
- 소유자가 "그만"·"여기까지"라고 하면 그 시점 판정으로 종료한다. 통과하지 못한 축이 있으면 판정은 `보류`이고, 종료 요약에 그렇게 적는다.
- 소유자가 "답만 줘"라고 하면 모든 모범답안을 공개하되 판정은 `보류`로 남긴다. 공개는 이해가 아니기 때문이다. 종료 요약에 "다음 PR에서 같은 축을 다시 묻는다"를 남긴다.

### Step 6: 검증 (MUST)

렌더하기 전에 확인한다.

- [ ] 등급·사유·조정 내역이 스크립트 출력과 일치한다. 내렸다면 사유가 출력에 있다.
- [ ] 모든 모범답안이 `context`의 구체물을 인용한다. 일반 지식만으로 쓴 답안이 없다.
- [ ] 답변 모드(기본)에서는 모든 질문 아래에 답안 또는 `GAP`이 있고, 판정·채점 문구가 없다.
- [ ] 채점 모드의 질문 라운드에 모범답안·판정 힌트가 새지 않았다.
- [ ] 예/아니오로 답할 수 있는 질문이 없다.
- [ ] `diff_truncated: true`면 잘린 hunk에 의존하는 답안이 없고 범위 줄에 그 사실이 있다.
- [ ] 요약 모드에 검증 장치와 "장치가 덮지 않는 것"이 있다.
- [ ] em dash와 이모지가 없다.

실패 시:
- `error: collector missing` → `task:understand-quiz` 스킬의 `collect_work_context.py`가 없다. 그 스킬을 먼저 복구한다.
- `error: No PR found and the local diff is empty` → 리포 안에서 실행하거나 `--ref`를 준다.
- `gh_error`가 있고 `source: local-branch`면 PR이 아직 없는 것이다. 범위 줄에 "PR 미생성, 로컬 브랜치 기준"을 쓴다.

## 주의사항

- 등급 규칙과 그 원리는 `references/grade-rules.md`에 있다. 규칙을 바꿀 때는 `scripts/grade_rules.json`과 그 문서를 함께 고친다. 규칙만 보려면 `triage_pr.py rules`, 경로만 시험하려면 `triage_pr.py classify --path ...`.
- 이 스킬은 정확성 리뷰를 하지 않는다. 버그 탐색은 `/code-review`, 구조·디자인 리뷰는 리뷰어 에이전트 몫이다. 이 스킬은 그 리뷰들이 통과한 뒤 "그래서 이것이 내 작업인가"를 묻는다.
- `env` 판정은 경로 토큰(`prod`, `stg`, `dev`, `global`)에만 의존한다. 경로에 환경이 없는 리포에서는 `flags`에 `prod`가 빠질 수 있으므로 Step 3에서 보정한다.
- 세션이 여러 개일 때는 PR마다 이 스킬을 따로 돌린다. 한 번에 여러 PR을 합쳐 묻지 않는다. 동시에 A등급 PR이 둘 이상이면 그 사실을 첫 줄에 적는다.
