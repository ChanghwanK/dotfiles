## 원칙

- 본문은 채택 대상 주장을 모두 담는다. 줄이는 곳은 요약 섹션뿐이다
- 문체는 `~/.claude/docs/notion-writing-style.md`를 따른다(평서체 ~다, 두괄식, em dash 금지, 이모지 금지)
- 원리·흐름은 평문 단락으로 먼저 설명하고, 개별 사실은 그 아래 불릿으로 쓴다. 사실 불릿만 나열하지 않는다
- 인용은 초안에서 `[@cNNN]`, render 후 `[[n]](url)`

## 섹션별 규칙

### 요약 (`## 요약`)
- 첫 불릿이 질문에 대한 결론이다. 이어서 결론을 받치는 핵심 근거 5~8개
- 불릿마다 인용
- 마지막 줄: `검증: 주장 <K>건 중 SUPPORTED <a>, PARTIAL <b>(조건 반영), 상충 <c>, 제외 <d> · 보고서 반영률 <r>%`

### 배경과 개념 (`## 배경과 개념`)
- 평문 2~4단락: 이 기능·개념이 없을 때 무엇이 문제였고, 무엇을 바꾸며, 핵심 용어는 무엇인가
- 단락 안 사실 문장마다 인용

### 서브질문 섹션 (`## <발견을 말하는 제목>`)
- 제목은 주제가 아니라 발견이다. 예: "축소는 kubelet이 메모리 사용량을 먼저 확인한다"(좋음) / "메모리 축소"(나쁨)
- 첫 단락(평문 2~5문장): 그 서브질문의 답과 원리
- 이어서 `###` 소주제별 사실 불릿. 그 서브질문의 채택 대상 주장을 모두 쓴다
- 비교 축이 둘 이상이면 표, 흐름·단계·상태 전이는 도식(`<!-- diagram: ... -->`)
- 내려받은 그림은 관련 문단 뒤에 넣고, 바로 아래 줄에 `그림: <설명> · [출처](<page>) (<license>)`. 게재할 수 없는 그림은 `관련 그림: [<설명>](<page>)`
- PARTIAL 주장은 조건을 문장 안에 쓴다. 상충은 `소스 상충: A는 X라고 한다 [n]. B는 Y라고 한다 [m].`

### 사용 예시 (`## 사용 예시`)
- 공식 문서·코드에 있는 예시(YAML, 명령, API 요청)를 원장 주장의 quote 그대로 코드 블록에 옮긴다. 고쳐 쓰거나 조합하지 않는다
- 블록마다 위에 한 줄 설명과 인용, 아래에 결과·주의점 불릿
- 원문 예시가 없으면 섹션을 "공식 예시 없음"으로 두고 지어내지 않는다

### 운영 권고 (`## 운영 권고`)
- 본문 주장에서 도출한 실행 항목 체크리스트(`- [ ]`). 항목마다 근거 주장 인용
- 근거 없는 일반론("모니터링을 강화한다")은 쓰지 않는다

### 검증 결과 (`## 검증 결과`)
- 표: 판정 | 건수 | 처리 (SUPPORTED 채택 / PARTIAL 조건 반영 / REFUTED·UNVERIFIABLE 제외 또는 상충 표기)
- 재판정한 주장마다 한 줄: `<주장 요약>: codex <판정> → 재판정 <결론> (<근거 한 줄>)`
- 초안 검증: 지적 <n>건, 반영 <m>건, 반영하지 않은 지적과 이유

### 수집 브리핑 (`## 수집 브리핑`)
- `manifest.py stats` 표를 그대로 옮긴다(숫자를 고쳐 쓰지 않는다). 보고서 반영률 행 포함
- 실패·빈약 URL이 있으면 개수와 대표 사유

### 한계와 미확인 (`## 한계와 미확인`)
- 답을 찾지 못한 핵심 질문(notes의 `## 빈 곳`)
- codex_failed로 검증하지 못한 주장 수, 의도적 미사용 주장 수와 대표 사유
- 원문 스냅샷 없이 WebFetch 요약으로만 읽은 소스 수

### 출처 (`## 출처`)
- `references.md`를 그대로 붙인다: `n. [제목](url) (tier, type, date)`
