# 가설 장부 (Hypothesis Ledger)

전역 CLAUDE.md 9번(Hypothesis-First)의 "판정과 갱신" 항목이 쓰는 기록입니다. 가설 한 건당 한 줄, 판정일에 결과를 채웁니다.
할 일 목록이 아닙니다(할 일은 Notion Task). 이 파일은 가설이 적중했는지, 빗나갔다면 모델의 어느 믿음이 수정됐는지를 누적하는 기록이며, 규칙 개정의 유일한 근거입니다.

## 기록 규칙

- 가설을 쓴 시점에 행을 추가하고 결과는 `미판정`으로 둡니다. 판정일에 결과를 채웁니다
- 결과 값: `적중` / `빗나감` / `미판정` / `검증 불가`(결과 판정 기회가 없고 강제 유발도 불가능했던 경우)
- `수정된 믿음`은 빗나감일 때 필수입니다. "예측 실패"가 아니라 모델의 어느 믿음이 어떻게 바뀌었는지를 씁니다. 적중이면 비워 두거나 "기준 느슨 의심"처럼 검증 기준 자체에 대한 메모를 둡니다
- 링크는 PR, Notion Task, 플랜 파일 중 하나입니다

## 집계 (월 1회, 규칙 개정 전 필수)

```bash
# 전체 행 수
grep -c '^| 20' ~/.claude/docs/hypothesis-ledger.md
# 결과별 건수
grep '^| 20' ~/.claude/docs/hypothesis-ledger.md | awk -F'|' '{print $6}' | sort | uniq -c
```

- 판정 완료율 = (적중 + 빗나감 + 검증 불가) / 전체. 낮으면 규칙이 작동하지 않는 것(비용 또는 판정 기회 부재)
- 빗나감률 = 빗나감 / 판정 완료. 계속 0이면 검증 기준이 느슨하다는 신호
- 규칙 개정은 빗나감의 공통 원인에서만 도출합니다. 사고 1건으로 필드를 추가하지 않습니다
