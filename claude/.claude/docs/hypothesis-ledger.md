# 가설 장부 (Hypothesis Ledger)

`docs/hypothesis-first.md` "판정과 갱신"이 쓰는 기록입니다. 가설 한 건당 한 줄, 판정일에 결과를 채웁니다.
판정을 기다리는 가설의 단일 대기열이자, 가설이 적중했는지·빗나갔다면 모델의 어느 믿음이 수정됐는지를 누적하는 기록이며, 지침 개정의 근거입니다.

## 기록 규칙

- 가설을 쓴 시점에 행을 추가하고 결과는 `미판정`으로 둡니다. 플랜의 `## 후속 판정` 항목은 플랜 승인 때 `scripts/ledger.py import-followups`가 자동으로 추가합니다(가설 열이 `(플랜 후속 판정)`으로 시작)
- 결과 열은 열거값만 씁니다: `적중` / `빗나감` / `미판정` / `검증 불가`(판정 기회가 없고 강제 유발도 불가능). 적용 직후와 결과의 판정이 다르면 `적용 직후 적중, 결과 미판정`처럼 두 값으로 씁니다. 세부 내용은 "수정된 믿음" 열에 씁니다
- 판정일 열에 날짜가 둘이면(`적용 직후 / 결과`) 결과 쪽 판정은 뒤 날짜에 합니다
- `수정된 믿음`은 빗나감일 때 필수입니다. "예측 실패"가 아니라 모델의 어느 믿음이 어떻게 바뀌었는지를 씁니다. 적중이면 비워 두거나 "기준 느슨 의심"처럼 검증 기준 자체에 대한 메모를 둡니다
- 셀 안의 `|`는 `\|`로 씁니다
- 링크는 PR, Notion Task, 플랜 파일 중 하나입니다

## 집계 (월 1회, 지침 개정 전 필수)

```bash
python3 ~/.claude/scripts/ledger.py stats     # 결과별 건수, 판정 완료율, 빗나감률
python3 ~/.claude/scripts/ledger.py overdue   # 판정일이 된 미판정 행 (SessionStart 훅은 하루 한 번 자동 표시)
```

- 판정 완료율 = (적중 + 빗나감 + 검증 불가) / 전체. 낮으면 규칙이 작동하지 않는 것(비용 또는 판정 기회 부재)
- 빗나감률 = 빗나감 / 판정 완료. 계속 0이면 검증 기준이 느슨하다는 신호
- 규칙 개정은 빗나감의 공통 원인에서만 도출합니다. 사고 1건으로 필드를 추가하지 않습니다
