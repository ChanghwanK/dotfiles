# 검증 시나리오 작성 규칙

정본입니다. 사람이 읽는 문서(업무 노트, PR 본문, wiki, 플랜 DoD)에 검증 시나리오·테스트 케이스·DoD 판정 기준을 쓸 때 따릅니다.
기계가 읽는 입력(`test_rules` payload 등)은 대상이 아니며, 그 입력을 만들 때는 아래 "Given/When/Then 세 줄 형식"에서 옮깁니다.
BDD(Given/When/Then, Specification by Example)의 작성 규칙을 차용하되, 형식은 한국어 한 문장을 유지합니다.

## 가설과의 관계

시나리오 문장은 가설의 검증 기준을 관측 단위로 쪼갠 것입니다(`docs/hypothesis-first.md`). 문제·가설·반증 조건·안 바뀔 것을 대신하지 못합니다.
먼저 문제와 가설(검증 기준)을 쓰고, 검증 기준마다 이 형식의 시나리오를 답니다. 업무 노트에서는 Goals가 이 시나리오입니다.

## 문서 구조 (영역마다 이 순서)

1. **규칙 머리말**: 검증하는 규칙을 한 문장으로 정의하고 경계값을 적는다. 문장에 반복되는 조건 이름("제외 조건" 등)은 여기서 한 번만 정의한다
2. `*방법:*` 무엇을 어떻게 일으키고 어디서 관측하는가. 내부 값 확인(설정값, 룰 식 결과)은 여기에 둔다. 검증 설계의 요약이다
3. `*시나리오와 결과:*` 시나리오 문장 목록. 각 문장 아래에 확인 의도를 별도 불릿으로 둔다

## 문장 형식

- 조건이 적용되는 경우: `{조건}이 적용된 경우, {상황}해도 {결과}해야 한다.`
  - 예: "제외 조건이 적용된 경우, 생성 5분 된 노드에 파드 20개가 동시에 기동해 CPU가 100%가 되어도 Slack에 알림이 오지 않아야 한다."
- 조건이 적용되지 않는 경우: `{상황}은 {이유}로 {조건}이 적용되지 않기 때문에, {상황}하면 {결과}해야 한다.`
  - 예: "생성 11분 된 노드는 600초가 지나 제외 조건이 적용되지 않기 때문에, CPU 100%가 알럿 지속 시간을 넘겨 유지되면 Slack에 알림이 와야 한다."
- 실측은 문장 끝 괄호: `(결과: 오지 않음)`, 판정 전이면 `(대기)`. 결과를 지어내지 않는다
- 시나리오는 관찰 기록이 아니라 기대 명세라 "~해야 한다"로 쓴다
- 표·기호(A~F)·숫자 열 표는 쓰지 않는다

## 작성 규칙

1. **문장 하나에 사건 하나**: 사건이 둘이면 문장을 나눈다. 결과가 어긋났을 때 어느 사건 때문인지 가릴 수 있어야 한다
2. **결과는 운영자가 보는 곳에서**: 결과 자리에는 운영자·사용자가 실제로 관측하는 것(Slack 알림, 노드 Ready, 응답 코드)을 쓴다. 내부 값은 `*방법:*`으로 내린다. 내부 값은 맞는데 관측 결과가 틀린 경우(라우팅, `for`, 다른 경로의 장애)를 놓치지 않기 위해서다
3. **억제와 발화를 쌍으로**: 조건이 적용되는 문장과 적용되지 않는 문장을 함께 둔다. 억제만 검증하면 조건이 정상 동작까지 막는지 모른다
4. **예시는 경계에서 고른다**: 경계 양쪽 예시를 쌍으로 둔다. 규칙과 무관한 부수 값은 빼고, 규칙의 경계값은 숨기지 않는다
   - 알럿은 경계값이 아니라 결과가 관측 가능해지는 시점을 기준으로 양쪽을 잡는다. `for`가 있으면 600초 제외 창을 벗어난 노드는 빨라야 600초 + `for`에 발화하므로, 억제 쪽은 창 안쪽, 발화 쪽은 경계 + `for` 이후에 판정한다

## Given/When/Then 세 줄 형식 (예외)

기본은 한 문장입니다. 아래 두 경우에만 세 줄로 씁니다.
- 자동화 테스트로 옮길 때: Given·When = `input_series`, 판정 시각 = `eval_time`, Then = `exp_alerts`로 vmalert `test_rules`에 대응한다. `exp_alerts`는 vmalert 안의 상태만 검증하고 Slack 도착은 검증하지 않으므로, 도착 확인은 `*방법:*`에 별도로 남긴다
- 전제가 셋 이상이라 한 문장이 늘어질 때

```
Given 생성 5분 된 노드 (제외 조건 적용)
  And 파드 20개가 동시에 기동 중
When  CPU 100%가 알럿 지속 시간을 넘겨 유지된다
Then  Slack에 알림이 오지 않아야 한다
```

## 영문 문서

같은 구조를 영어로 씁니다.
- "When {condition} applies, {situation} must not {result}."
- "{situation} does not meet {condition} because {reason}, so {result} must happen."

## 작성 후 점검

- 모든 문장에 적용 조건(또는 적용되지 않는 이유)이 들어 있는가
- 사건이 둘인 문장이 있는가 → 분리
- 결과 자리에 내부 값이 들어갔는가 → `*방법:*`으로 이동, 관측 결과로 교체
- 억제·발화 쌍과 경계 양쪽 예시가 있는가
- 실측 전 결과를 채우지 않았는가 (`(대기)`)
