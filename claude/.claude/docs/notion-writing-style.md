# Notion 문서 작성 스타일

원칙: **짧고 단순하게, 핵심만.** 길고 복잡한 문장보다 짧고 읽기 쉬운 문장을 우선한다.

## 쓰기 시점 체크리스트

작성 스킬(notion:add-*, tasks:capture)은 **초안을 쓰는 시점에** 아래를 직접 적용한다.
자동 교정 안전망은 없으므로 1차 작성이 곧 최종 품질이다.

- `레이블: 내용` 구조는 레이블을 불릿 없는 평문 문단 `레이블:`로 쓰고, 내용을 그 아래 최상위 불릿으로 쓴다. 레이블에는 기울임·볼드·색상을 적용하지 않는다. 내용이 한 줄이어도 레이블 줄에 붙이지 않는다 (상세: `## 구조` 레이블 규칙, TOC 라벨 예외 포함).
- 불릿 들여쓰기는 한 단계까지만 쓴다.
- 목차 블록은 회색 텍스트(`color: gray`)로 둔다.
- 버전/태그/backtick 값 전환은 "to" 대신 화살표(`→`)로 직접 쓴다 (상세: `## 문장`). 숫자 버전/backtick 값 쌍은 쓰기 스크립트(`notion_text.py`)가 결정적으로도 치환한다.
- Goals/Non-Goals류 구조적 섹션은 볼드 텍스트가 아니라 실제 헤딩(`##`/`###`)으로 직접 쓴다 (상세: `## 구조`, TOC 라벨 예외 제외).
- 여러 섹션에 같은 사실을 재진술하지 않는다: 한 사실은 가장 적합한 섹션에만 쓴다 (상세: `## 구조`).
- Summary/불릿 목록은 결론·핵심 판단을 첫 불릿에 둔다 (상세: `## 문장` 두괄식).
- 코드 블록은 실행형 명령어/설정 전체에만 쓰고, 일반 명사·강조 목적으로 쓰지 않는다 (상세: `## 코드 블록 사용 기준`).
- em dash·이모지는 전역 CLAUDE.md 규칙을 따르며, 쓰기 스크립트가 결정적으로도 제거한다.
- 업무 노트 `## 실행 기록`은 액션 단위로 쓴다: 행위 동사 레이블(`날짜, ~을 적용 (PR #N):`) + 결과 1~2불릿. 절차 단계·명령어·HH:MM·커밋 해시는 쓰지 않는다 (상세: `## 실행 기록 (업무 노트)`).

## 문장

- 평서체(~다)로 쓴다.
- 한 문장 한 메시지가 기본이나, 기계적으로 모든 문장을 끊지 않는다. **서로 무관한 사실은 짧게 끊고, 서로 밀접한 사실(비교/대구, 결론+바로 그 근거, 원인+결과)은 자연스러운 연결어(~이며, ~고, ~는데, ~므로)로 한 문장에 묶는다.** 무관한 절을 쉼표로 나열해 늘어지는 문장(예: A하고, B하며, C한다)은 여전히 금지한다. 목표는 공식 문서체다: 뚝뚝 끊긴 "~다. ~다. ~다." 나열도, 늘어지는 만연체도 아닌, 절제되게 연결된 서술.
  - 예 (지향, 무관한 사실 나열 시): 이 옵션은 캐시를 비활성화한다. 기본값은 `false`이다. 설정 변경 후 Pod가 재시작된다.
  - 예 (지양, 무관한 절을 쉼표로 나열): 이 옵션은 캐시를 비활성화하는데, 기본값은 false이며 설정을 변경하면 Pod가 재시작된다.
  - 예 (지향, 밀접한 비교/대구를 한 문장으로): tech/ai-realmate만 전환 가치가 있으며, observability/loki(read, gateway)는 전환을 권장하지 않는다.
  - 예 (지양, 같은 비교를 억지로 끊음): tech/ai-realmate만 전환 가치가 있다. observability/loki(read, gateway)는 전환 비권장한다.
  - 예 (지향, 결론+근거를 한 문장으로): tech/core-api는 7일간 야간 50~60rps에서 피크 400~590rps로 약 10배의 diurnal 스윙을 보이며, 이는 다른 정적 replicaCount 후보들보다 절대적으로 크다.
  - 예 (지양, 결론과 바로 이어지는 근거를 억지로 끊음): tech/core-api는 7일간 야간 50~60rps → 피크 400~590rps로 약 10배 diurnal 스윙을 보인다. 다른 정적 replicaCount 후보들보다 절대적으로 크다.
- 한 불릿 안에 서로 다른 요지(각기 다른 근거·사례·제안)를 문장 단위로 이어붙이지 않는다. 두 문장이 원인+결과·조건+결과처럼 진짜 하나의 생각인 경우가 아니면, 불릿을 나눠 각 불릿이 "~다."로 한 번만 끝나게 한다. 회고(잘된 점/아쉬운 점/다음에 다르게 할 것), Lessons처럼 여러 요지를 나열하는 섹션에서 특히 흔한 함정이다: 개별 문장은 규칙대로 짧게 썼어도, 불릿 하나에 요지 2~3개를 눌러 담으면 전체적으로 "~다. ~다. ~다."가 반복돼 가독성이 떨어진다.
  - 예 (지향, 서로 다른 요지는 불릿을 분리):
    - office 클러스터가 ClusterPolicy CR 부재로 이 시나리오를 검증할 수 없다는 걸 계획 단계에서 먼저 확인했다면 불필요한 계획 수정 왕복을 줄일 수 있었다.
    - labelWhiteList가 라벨 네임스페이스를 가리지 않는다는 메커니즘을 nvidia.com 라벨까지 포함해 처음부터 조사했다면 helm template 단계에서 바로 정답 정규식이 나왔을 것이다.
  - 예 (지양, 서로 다른 요지를 한 불릿에 이어붙임): office 클러스터가 ClusterPolicy CR 부재로 이 시나리오를 검증할 수 없다는 걸 계획 단계에서 먼저 확인했다면 불필요한 계획 수정 왕복을 줄일 수 있었다. labelWhiteList가 라벨 네임스페이스를 가리지 않는다는 메커니즘을 nvidia.com 라벨까지 포함해 처음부터 조사했다면 helm template 단계에서 바로 정답 정규식이 나왔을 것이다.
- 군더더기를 빼고 핵심만. 쉬운 표현을 쓴다.
- 두괄식을 기본으로 한다: 결론·핵심을 맨 앞에 둔다. 설득·논증·학습 서사가 목적일 때만 전개식(미괄식)을 의식적으로 선택한다.
- 불릿 목록도 두괄식으로 정렬한다: 여러 불릿을 나열할 때 결론·핵심 판단(접근 방법, 해결책 등)을 첫 불릿에 두고 배경·현황 설명을 뒤에 둔다. Summary를 대상 → 현황 → 접근 순서로 기계적으로 나열하지 않는다.
- 능동태, 주어를 명확히.
- 산문은 한국어, 코드·명령어·식별자는 영어 원문을 유지한다.
- 한 개념엔 한 용어. 약어는 첫 등장 시 한 번 풀어쓴다.
- 모호어("잘 된다") 대신 측정 가능한 표현을 쓴다.
- 전후·방향 전환을 나타낼 때 "to" 대신 화살표(`→`)를 쓴다. 예: `0.59.3 → 0.84.0`, `수정 전 → 수정 후` (resume-format-convention.md의 화살표 표기 관행을 일반 문서에도 적용).

## 구조

- 긴 문단 대신 불릿으로 쪼갠다.
- 제목은 H1 → H2 → H3 순서로, 단계를 건너뛰지 않는다.
- 비교는 표, 열거는 불릿, 절차는 번호 목록.
- 볼드·콜아웃은 핵심에만. 인라인 코드는 식별자·값에.
- `레이블: 내용` 패턴은 레이블을 불릿 없는 평문 문단으로 쓰고, 내용을 그 아래 최상위 불릿으로 쓴다. 레이블에는 기울임·볼드·색상을 적용하지 않는다.
  - **레이블 규칙**: 레이블 줄에는 불릿을 달지 않는다. 내용은 레이블 바로 아래 최상위 불릿(들여쓰기 없음)으로 쓰고, 내용이 한 줄뿐이어도 레이블 줄에 인라인으로 붙이지 않는다. 내용 불릿에 세부가 필요하면 한 단계만 들여쓴다. 레이블 묶음 사이에는 빈 줄을 둔다. PAR(Problem/Action/Result), 상황/문제/대안, 측정 항목(안정성/생산성/지식부채 등)처럼 레이블 아래 설명이 붙는 구조에 모두 적용한다.
  - **도구 지원**: `notion-task.py append-content`(마크다운 → Notion 블록 변환)는 평문 줄을 문단 블록으로, `- ` 줄을 불릿으로, 들여쓴 불릿을 `children` 중첩으로 변환한다. 이 레이블 형식은 중첩이 한 단계뿐이라 한 번 append의 2단계 중첩 제약에 걸리지 않는다.
  - **TOC 서브 라벨 예외**: `notion-eng-note.py`(독립 노트의 `goal`/`non_goal` 섹션)와 `notion-task.py`(5-필드 템플릿의 `Goals`/`Non-Goals`)는 페이지 상단 TOC 콜아웃이 각 항목에 개별 링크를 걸 수 있도록, 스크립트가 직접 **평문 "Goal"/"Non-goal"/"Goals"/"Non-Goals" 라벨**을 생성한다(`_lib/notion_toc.py`의 `_SUB_LABELS` 참조). 이 두 경로는 아래 "Goals/Non-Goals 헤딩화" 규칙과 위 레이블 규칙 모두의 의도된 예외이며, 실제 헤딩이나 문단 레이블로 바꾸지 않는다.
- 긴 부차 정보(로그, 출력)는 토글로 접는다.
- 리스트 중첩은 2단계(최상위 불릿 + 한 단계 들여쓰기)까지.
- 링크는 의미 있는 텍스트에 건다.
- 섹션 간 동일 사실을 재진술하지 않는다. 한 사실은 가장 적합한 섹션에서 한 번만 서술한다. 트러블슈팅 기록에서 `작업 내용`·`작업 로그` 섹션은 앞 섹션(요약·원인·해결·교훈)에서 이미 말한 내용을 반복하지 않고, 그곳에만 있는 고유 정보(PR·산출물·수동 조치 등)만 남긴다.
- Goals/Non-Goals, 목표/비목표처럼 문서를 구조적으로 나누는 섹션은 인라인 볼드 레이블이 아니라 실제 헤딩(H2/H3)으로 작성한다. 볼드 텍스트만으로 섹션을 구분하지 않는다. (단, 위 "TOC 서브 라벨 예외"에 해당하는 `notion-eng-note.py`/`notion-task.py`의 스크립트 생성 라벨은 제외.)

## 실행 기록 (업무 노트)

업무 노트의 `## 실행 기록`은 `### 실행 계획`(체크박스 + `롤백:`)과 `### 진행 기록`으로 나뉜다. 아래 규칙은 `### 진행 기록`에 적용한다(계획 체크박스는 그대로). 진행 기록은 **사람이 읽는 액션 단위 일지**다. 절차 단계(머지 → sync → 적용 확인)나 명령어·쿼리 수준으로 쪼개지 않는다.

- **항목 = 의사결정 하나가 끝나는 단위**: 변경 하나와 그 결과를 한 항목에 담는다. "PR 오픈"처럼 결과가 없는 절차 단계는 항목으로 두지 않고, 결과가 나온 항목의 첫 문장에 녹인다.
- **레이블은 행위 동사로 끝나는 문장**: `YYYY-MM-DD, {대상}을 {적용·제거·추가·검토·확인·할당} (PR #N):` 형태. 명사구(`GOGC override 제거`)가 아니라 동사형(`GOGC=100 override를 제거`)으로 쓴다. 예측이 빗나간 항목은 레이블에 `예측 실패를 확인`을 넣어 독립 항목으로 둔다.
- **내용 불릿은 2개 안팎**: 첫 불릿은 무엇을 했고 어떤 결과가 나왔는가, 둘째 불릿은 남은 판정이나 다음 조치.
- **남기는 수치는 판정에 쓰인 값만** (`2.0 → 1.3`, 설정값). 시각은 날짜까지만 적고 HH:MM은 쓰지 않는다. 커밋 해시·파드 이름·확인 쿼리·플래그 목록은 PR 본문과 Task `작업 Context` 산출물에 두고 실행 기록에서는 뺀다.
- 예 (지향): `2026-10-13, 쿼리 메모리 상한 관측과 JSON 로그 포맷을 적용 (PR #9401):` 아래에 "vmsingle에 `search.logQueryMemoryUsage=500MB`와 JSON 로그 포맷을 넣었다. ArgoCD sync 후 Loki에 vmsingle JSON 로그가 level 라벨과 함께 들어와 적용 직후 검증 기준을 충족했다." / "다음 판정: 10-19 상한 거부 7일 추이."
- 예 (지양): `2026-10-13 15:39 KST, PR #9401 머지:`, `15:41 KST, 적용:`, `15:42 KST, 적용 확인:`처럼 절차 단계별 3항목에 커밋 해시·파드 이름·`/flags` 출력·쿼리를 나열하는 것 (2026-10-13 vmsingle GOGC 노트에서 교정).

## 코드 블록 사용 기준

인라인 코드(`` ` ``)와 코드 펜스(```` ``` ````)를 적절하게 구분한다.

- 업무 노트(Engineering DB)와 Task 본문의 인라인 코드는 글자색을 빨강으로 쓴다. `notion-eng-note.py`(노트 생성)와 `notion-task.py`(Task 생성·덧붙이기, 노트 append-content)가 적용한다(2026-10-14 사용자 지정). 코드 펜스는 Notion이 문법 하이라이트로 렌더링해 글자색을 지정할 수 없다.

**인라인 코드 사용 (올바른 경우):**
- 명령어·CLI 플래그: `kubectl get pod`, `--dry-run`
- 식별자·키: `ceph_health_status`, `pool_id`, `bemfeemok4ge8c`
- 파일 경로: `src/observability/grafana/dashboards/ceph/`
- 설정 키·값: `max_avail`, `fstype!="tmpfs"`

**코드 펜스 사용 (올바른 경우):**
- 실행 가능한 명령어 블록 (2줄 이상이거나 복사해서 쓸 것)
- 설정 파일 내용 전체
- 로그·출력 결과 (긴 경우 토글로 접는다)

**코드 블록 남용 금지:**
- 일반 명사를 코드로 감싸지 않는다: `스토리지`, `대시보드` (X)
- 섹션 제목·레이블에 코드 블록 사용 금지
- 강조 목적으로 인라인 코드를 쓰지 않는다: 강조는 볼드(`**`)를 쓴다

## 하드룰
